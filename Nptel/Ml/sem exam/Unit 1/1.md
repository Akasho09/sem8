# 🔄 Machine Learning Development Life Cycle (MLDLC)
- MLDLC is a step-by-step pipeline used to develop ML models from problem definition to deployment and monitoring.
> PDD EF M TED M

1. Problem Definition
Clearly define the objective
- Identify:
    Input (features)
    Output (target)
- Decide type of problem:
    Classification / Regression / Clustering
- 👉 Example: Predict house prices (Regression)

2. Data Collection
- Gather data from:
    Databases
    APIs
    Sensors
    Web scraping
- 👉 Data quality directly impacts model performance

3. Data Preprocessing
    Handle missing values
    Remove duplicates
    Normalize/standardize data
    Encode categorical variables
- 👉 Raw data → Clean data

4. Exploratory Data Analysis (EDA)
Understand data patterns
- Use:
    Graphs (histograms, scatter plots)
    Correlation analysis
- 👉 Helps in feature selection

5. Feature Engineering
- Create new useful features
Select important features
- Reduce dimensionality (PCA)
- 👉 Improves model accuracy significantly

6. Model Selection
- Choose algorithm based on problem:
    Linear Regression → simple data
    Decision Trees → interpretable
    Neural Networks → complex patterns

7. Model Training
- Split data:
Training set
Validation set
Train model on training data

8. Model Evaluation
- Test model performance using:
    Accuracy
    Precision, Recall
    F1-score
    RMSE (for regression)
- 👉 Detect overfitting / underfitting

9. **Hyperparameter Tuning**
Optimize model parameters
- Techniques:
    Grid Search
    Random Search

10. Model Deployment
Deploy model into real-world system:
Web app (using APIs)
Mobile app
Cloud (AWS, Azure, GCP)

11. Monitoring & Maintenance
Track performance over time
- Handle:
Data drift
Model degradation
Retrain when needed

- 🔁 Lifecycle Flow (Short Form)
> Problem → Data → Preprocess → EDA → Features → Model → Train → Evaluate → Deploy → Monitor

```yml
Problem Definition
        ↓

        ↓

        ↓

```

# 🔹 4. Bias-Variance Tradeoff
- Total Error Decomposition:
> Error=Bias^2+ Variance+ Irreducible Error

1.  🔹 Bias
> inability of model to learn training data
- Error due to oversimplified model
- Model assumptions are too strong
- 👉 Example:
- Linear model for non-linear data
- 📉 Leads to:
    - Underfitting

2. 🔹 Variance
- Error due to model sensitivity to data
- Model changes a lot with small data changes
- 📈 Leads to:
    - Overfitting

# Reinforcement Learning 
- is a type of machine learning where an agent learns by interacting with an environment and improves its behavior using rewards and penalties.

## 🔹 Core Components
1. Agent
The learner/decision maker
👉 Example: Robot, game player

2. Environment
The world the agent interacts with
👉 Example: Game board, real world

3. State (S)
Current situation of the agent

4. Action (A)
Choices the agent can take

5. Reward (R)
Feedback from environment
Can be positive or negative

## 🔁 Basic Working
1. Agent observes state (S)
2. Takes an action (A)
3. Environment returns:
    - New state
    - Reward
4. Agent updates its strategy
👉 Goal: Maximize total reward over time

## 🔹 Key Concept: Policy
> A policy (π) is a strategy used by the agent
- It maps:
👉 State → Action

## 🔹 Value Functions
- State Value (V) → how good a state is
- Action Value (Q) → how good an action is in a state

## 🔹 Popular Algorithms
1. Q-Learning
Model-free algorithm
Learns optimal policy using Q-values

2. SARSA
Similar to Q-learning but more conservative

3. Deep Q Network (DQN)
Uses neural networks for complex problems

## 🔹 Exploration vs Exploitation
- Exploration → Try new actions
- Exploitation → Use known best action

👉 Balance is very important

## 🔹 Applications
🎮 Game playing (Chess, Atari, Go)
🤖 Robotics
🚗 Self-driving cars
💰 Trading systems
📊 Recommendation systems

## 🔥 Advantages
Learns from interaction (no labeled data needed)
Can solve sequential decision problems

## ⚠️ Challenges
Needs lots of data/time
Reward design is tricky
Can be unstable in complex environments

# 🔹 Instance-Based Learning (Lazy Learning)
- Stores training data and learns only when a query is made.
- No explicit model is built beforehand.
- Prediction is based on similarity (distance) to stored examples.
- Key Features:
    - Training time: Low
    - Prediction time: High
    - Memory: High (stores data)
- Example:
    - k-Nearest Neighbors (k-NN)
- Pros:
    Simple, flexible
    Adapts quickly to new data
- Cons:
    Slow during prediction
    Sensitive to noise and irrelevant features

# 🔹 Model-Based Learning (Eager Learning)
- Builds a generalized model from training data.
- Learns parameters and relationships during training.
- Key Features:
    - Training time: High
    - Prediction time: Fast
    - Memory: Low (stores model, not data)
- Example:
    - Linear Regression, Logistic Regression, Neural Networks
- Pros:
    Fast predictions
    Better generalization
- Cons:
    Requires training
    May underfit/overfit if model choice is poor

| Feature         | Instance-Based | Model-Based       |
| --------------- | -------------- | ----------------- |
| Learning type   | Lazy           | Eager             |
| Model building  | No             | Yes               |
| Training time   | Low            | High              |
| Prediction time | High           | Low               |
| Memory usage    | High           | Low               |
| Example         | k-NN           | Linear Regression |
