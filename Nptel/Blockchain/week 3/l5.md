# Blockchain Elements – III

## 📜 1. Bitcoin Scripts
- Small programs used to control spending of bitcoins
- Purpose:
    - Ensure:
        - Correct ownership
        - Secure transfer
        - Controlled access

## 🔄 2. Transaction Input vs Output
- 🔹 Output (ScriptPubKey)
    - Created when sender sends money
    - Defines who can spend coins
- 🔹 Input (ScriptSig)
    - Used when receiver spends coins
    - Provides proof of ownership
- Key Flow:
    - Sender → ScriptPubKey → Locks coins
    - Receiver → ScriptSig → Unlocks coins

## 🔐 3. Pay-to-Public-Key-Hash (P2PKH)
- Payment made to hash of public key
- Why hash?
    - Improves privacy
    - Prevents identity tracking
- Flow:
    - Alice → pays to → hash(Bob’s public key)
    - Bob → proves ownership using → private key

## ⚙️ 4. Stack-Based Script Execution
- Scripts are executed using a stack
- Properties:
    - LIFO (Last In First Out)
- Operations:
    - Push
    - Pop
    - Execute
- Execution Flow:
```yml
        ScriptSig + ScriptPubKey → Combined Script
            ↓
        Executed step-by-step
            ↓
        Final result = TRUE → Valid transaction
```

## 🧠 5. Script Operations (OP Codes)
- Common Operations:
1. OP_DUP
Duplicates top stack item

2. OP_HASH160
Hashes top item

3. OP_EQUALVERIFY
Checks equality
Stops if false

4. OP_CHECKSIG
Verifies digital signature

## 🔍 6. Step-by-Step Execution (IMPORTANT)
- Initial Stack: Empty

1. Step 1:
- Push:
    - Signature
    - Public Key

2. Step 2: OP_DUP
- Duplicate public key

3. Step 3: OP_HASH160
- Hash duplicated public key

4. Step 4:
- Push expected public key hash

5. Step 5: OP_EQUALVERIFY
- Compare:
    - Computed hash == Expected hash

- ✔️ If TRUE → Continue
- ❌ If FALSE → Stop

6. Step 6: OP_CHECKSIG
- Verify signature using public key

- ✔️ If TRUE → Transaction valid

## 🔑 7. What Does This Ensure?
Payment intended for correct person
Only owner can spend coins

## 🔐 8. Signature Verification
- Logic:
```yml
    Encrypted with private key
            ↓
    Decrypted using public key
```
- Ensures:
    - Identity verification
    - Ownership proof

## 🌐 9. Real Bitcoin Transaction
- Observations:
    - Each transaction has:
        - Input scripts
        - Output scripts
- Example:
    - One input → multiple outputs
    - Each output has separate ScriptPubKey

## ✍️ 10. Multi-Signature Scripts
- Requires multiple approvals
- Example:
    - 2 out of 3 signatures required
- Use:
    - Joint accounts
    - Business transactions

## ⚠️ 11. Special Scripts
- 🔹 OP_RETURN
    - Stops execution immediately
- Used for:
    - Data storage
    - Invalid transactions
- 🔹 OP_TRUE
    - Always returns TRUE
    - Anyone can spend coins

## ⏳ 12. Time-Locked Transactions
Concept:
Funds locked until specific time
Operation:
OP_CHECKLOCKTIMEVERIFY
Example:
Funds available after 1 Jan 2026
Use Cases:
Contracts
Delayed payments

## ⚙️ 13. Script Design
Key Features:
Simple
Stack-based
Not Turing complete
Why?
Avoid infinite loops
Ensure fast execution
Improve security

## 🔗 14. Full Transaction Security Flow
Transaction created
↓
ScriptPubKey locks coins
↓
ScriptSig unlocks coins
↓
Stack execution verifies:
    - Public key hash
    - Signature
↓
If TRUE → Transaction accepted

# 📌 Final Summary
- Bitcoin uses scripts for transaction validation
- Combines:
    - Hashing
    - Digital signatures
    - Stack execution
