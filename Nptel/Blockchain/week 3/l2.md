# Smart Contracts and the Permissioned Models of Blockchain 

## Smart Contracts
- Smart contracts are self-executing programs stored on a blockchain that automatically enforce an agreement when predefined conditions are met.
👉 Think of them as:
> “If this happens → then do that” (automatically, without a middleman)
- 🔗 How they work:
    - A contract is written in code
    - It is deployed on a blockchain (like Ethereum)
    - Users interact with it (send inputs/transactions)
    - When conditions are met → it executes automatically
-  📌 Example:
- Online purchase without a middleman
    - Condition: Buyer sends payment
    - Smart contract checks payment
    - If valid → automatically releases product/service
    - If not → no action
✔ No bank, no broker, no manual verification

## Decentralized Code Execution
- In traditional systems, code runs on a single server. In blockchain, execution is distributed across many nodes.
- ✔ How it works:
    - Smart contract code is deployed on blockchain
    - Every node in the network:
    - Receives the transaction
    - Executes the same code
    - Verifies the output
- ✔ Key Properties:
    - Deterministic → Same input gives same output on all nodes
    - Trustless → No need to trust a central authority
    - Fault-tolerant → Even if some nodes fail, system works
- 👉 Example: Ethereum executes smart contracts across all participating nodes

## Centralized vs Decentralized Contract Execution
- 🔸 Centralized Execution:
    - Runs on a single server (e.g., bank server)
    - Faster but:
        - Vulnerable to hacks
        - Single point of failure
- 🔸 Decentralized Execution:
    - Runs on multiple nodes
    - More secure but:
        - Slower
        - Higher cost (gas fees)
- ✔ Key Insight:
- Centralized = Efficiency
- Decentralized = Security + Trustlessness

## 🔷 3. State Machine Model of Smart Contracts
- A smart contract behaves like a Finite State Machine (FSM).
- ✔ Concept:
    - Contract has states
    - Transactions cause state transitions
- ✔ Example (Escrow Contract):
    - State 1: Created
    - State 2: Funded
    - State 3: Released / Refunded
- ✔ Important:
    - State is stored on blockchain
    - Only valid transitions are allowed


## 🔷 4. Smart Contract Execution on Blockchain
- ✔ Execution Flow:
    - User sends transaction
    - Transaction reaches network
    - Smart contract code is triggered
    - Nodes execute code independently
    - Consensus mechanism validates output
    - Blockchain state is updated
- ✔ Gas Concept:
    - Execution requires gas fees (in Ethereum)
    - Prevents infinite loops and spam

## 🔷 5. DApps (Decentralized Applications)
- Applications whose:
    - Frontend → UI (React, etc.)
    - Backend → Smart contracts
    - ✔ Architecture:
    - Frontend ↔ Smart Contract ↔ Blockchain
- ✔ Features:
    - No central server
    - Open-source
    - Token-based economy
- ✔ Examples:
    - DeFi (Decentralized Finance)
    - NFT marketplaces
    - Voting systems

## 🔷 6. Blockchain 2.0
- ✔ Focus:
    - Beyond cryptocurrency
- Introduction of programmable logic
- ✔ Key Feature:
    - Smart contracts
- 👉 Example: Ethereum

## 🔷 7. Limitations of Public Blockchain
- ⚠️ Latency:
    - Delay in transaction confirmation
    - Due to block creation time
- ⚠️ Throughput:
    - Limited transactions per second
        - Bitcoin ≈ 7 TPS
        - Ethereum ≈ 15–30 TPS
- ⚠️ Other Issues:
    - High energy consumption (PoW)
    - Scalability challenges

## 🔷 8. Enterprise Requirements
- Organizations need:
✅ High throughput
✅ Low latency
✅ Privacy (data confidentiality)
✅ Permission control
✅ Regulatory compliance
👉 Public blockchain fails in these areas

## 🔷 9. Permissioned Blockchain
- Blockchain where:
    - Only authorized users can participate
- ✔ Features:
    - Controlled access
    - Faster consensus
    - Better privacy
- ✔ Examples:
    - Hyperledger Fabric
    - R3 Corda

## 🔷 10. Blockchain 3.0
- ✔ Evolution:
    - Blockchain 1.0 → Cryptocurrency (Bitcoin)
    - Blockchain 2.0 → Smart Contracts
    - Blockchain 3.0 → Real-world applications
- ✔ Focus Areas:
    - Scalability
    - Interoperability
    - Sustainability
- ✔ Use Cases:
    - Healthcare
    - Education
    - Governance

## 🔷 11. Trustless Decentralization
- No need to trust people or institutions
- Trust is replaced by:
    - Cryptography
    - Consensus mechanisms
- “Don’t trust, verify”


## 🔷 12. Classical Consensus vs Proof of Work (PoW)
- 🔸 Classical Consensus (PBFT, Raft):
    - Nodes are known and trusted
    - Faster and energy-efficient
- 🔸 Proof of Work (PoW):
    - Open participation
    - Requires solving cryptographic puzzles
    - Very secure but slow and energy-intensive


## 🔷 13. Witness Cosigning
- A set of trusted nodes (witnesses) sign blocks
- ✔ Benefits:
    - Faster validation
    - Reduced computation
    - Increased security
- ✔ Used in:
    - Permissioned or hybrid blockchains
