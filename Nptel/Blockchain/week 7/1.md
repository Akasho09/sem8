# PBFT Algorithm – Detailed Working & Quorum Concept

## 🔐 1. Why PBFT Needed?
- Problem with Previous Systems:
- Paxos → Handles Crash Faults only
- LSP Algorithm → Unrealistic assumptions:
    - Synchronous network
    - Reliable communication
    - Fully connected network
- Need:
    - Handle Byzantine faults in real (asynchronous) systems

## ⚙️ 2. What is PBFT?
- Practical Byzantine Fault Tolerance
- Consensus algorithm for asynchronous systems
- Key Idea:
    - Tolerate malicious nodes + reach consensus efficiently
- Important:
- Works with:
    - 3F + 1 nodes → tolerate F faulty nodes

## 🧠 3. PBFT Architecture
- Roles:
- 🔹 Primary (Leader)
    - Proposes value
    - Orders transactions
- 🔹 Backups (Replicas)
    - Validate proposal
    - Vote on correctness
- 🔹 Client
    Sends request
    Waits for final response
- Structure:
Client → Primary → Backups → Consensus → Client

## 🔄 4. View Concept
- A configuration of system with a leader (primary)
- Key Idea:
View change → New primary selected
Identification:
Each view has:
View number (v)
Rule:
Only messages from current view are accepted
⚙️ 5. PBFT Phases (VERY IMPORTANT)
🔹 Phase 1: PRE-PREPARE
Step:
Client sends request to primary
Primary:
Assigns sequence number (n)
Computes digest (d)
Broadcasts:
PRE-PREPARE(v, n, d, m)
Purpose:
Define ordering of transactions
Validation Conditions:
Signature correct
Message digest matches
No duplicate sequence number
Within threshold
🔹 Phase 2: PREPARE
Step:
Backups verify PRE-PREPARE
If valid → broadcast:
PREPARE(v, n, d)
Meaning:
"I agree with primary's proposal"
Key Role:
Acts as voting mechanism
🔹 Phase 3: COMMIT
Condition:
Receive 2F + 1 matching PREPARE messages
Step:
Send:
COMMIT(v, n, d)
Final Condition:
Receive 2F + 1 COMMIT messages → Commit transaction
🔗 6. Total Order Concept
Definition:
All nodes agree on same order of transactions
Example:
T1 → T2 → T4 → T3
Importance:
Ensures consistent state across nodes
🔐 7. Role of Cryptography
Used for:
Identity verification
Message integrity
Mechanism:
Private key → Sign message
Public key → Verify sender
Also includes:
Message digest (hash)
📊 8. Quorum Concept (VERY IMPORTANT)
Definition:
Minimum votes required for consensus
PBFT Quorum:
2F + 1 nodes
Why 2F + 1?
Case 1: Crash Fault
F nodes silent
Remaining 2F + 1 are correct

✔️ Easy consensus

Case 2: Byzantine Fault
F nodes malicious
From 2F + 1 votes:
At least F + 1 are honest

✔️ Majority still honest

🔁 9. Byzantine Dissemination Quorum
Properties:
🔹 Intersection
Any two quorums share ≥ 1 honest node
🔹 Availability
At least one quorum has no faulty nodes
Result:
Prevents conflicting decisions
📥 10. Message Flow Summary
Client → Request
↓
Primary → PRE-PREPARE
↓
Backups → PREPARE
↓
All nodes → COMMIT
↓
Consensus achieved
↓
Reply to client
🧠 11. Why PBFT Works?
Because:
Uses majority voting
Ensures overlap between quorums
Uses cryptographic verification
Handles asynchronous communication
📌 Final Summary
PBFT = BFT consensus algorithm
Works in:
Asynchronous networks
Malicious environments
Key Rules:
Nodes ≥ 3F + 1
Votes ≥ 2F + 1
