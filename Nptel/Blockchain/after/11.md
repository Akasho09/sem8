# Hyperledger Aries
- Hyperledger Aries is an open-source framework for building decentralized identity (DID) and self-sovereign identity (SSI) applications.
- It provides:
    secure peer-to-peer communication,
    credential exchange protocols,
    agent frameworks,
    DID-based messaging.
- Aries works closely with:
    Hyperledger Indy
    Verifiable Credentials standards
    DID standards.

- Main Goal of Hyperledger Aries
- To enable:
    trusted digital identity interactions,
    secure credential sharing,
    decentralized authentication,
    without centralized identity providers.
- Aries in the SSI Ecosystem
    Hyperledger Indy → Trust Ledger
    Hyperledger Aries → Communication & Agents
- Relationship Between Indy and Aries
| Hyperledger Indy        | Hyperledger Aries              |
| ----------------------- | ------------------------------ |
| Blockchain ledger       | Communication layer            |
| Stores DIDs and schemas | Exchanges credentials          |
| Provides trust anchor   | Provides interaction protocols |
| Identity infrastructure | Agent framework                |

- Core Components of Hyperledger Aries
| Component    | Purpose                    |
| ------------ | -------------------------- |
| Aries Agents | Autonomous identity agents |
| DIDComm      | Secure DID messaging       |
| Wallet       | Stores keys/credentials    |
| Protocols    | Credential exchange rules  |
| Mediators    | Routing communication      |

# selfish mining : 
- Selfish mining is a strategy in blockchain systems where a miner or mining pool intentionally hides newly mined blocks instead of immediately broadcasting them to the network.
- The goal is to:
    gain an unfair mining advantage,
    waste honest miners’ effort,
    and earn a larger share of mining rewards.
- Selfish mining mainly affects Proof-of-Work blockchains such as:
    - Bitcoin.
- Basic Idea
- Normally:
Miner finds block → Immediately broadcasts it
- In selfish mining:
Miner finds block → Keeps it secret temporarily
The selfish miner builds a private chain before revealing it strategically.
- Main Objective
- To make honest miners:
    mine on outdated blocks,
    waste computational power,
    lose rewards.
- Meanwhile, selfish miners increase their probability of earning rewards.

- How Selfish Mining Works
- Suppose:
selfish miners control part of network hash power.

- Step-by-Step Process
1. Step 1: Mine Secret Block
- Selfish miner discovers a block but does NOT broadcast it.
- Instead:
    keeps block private,
    starts extending private chain.

2. Step 2: Honest Network Continues Mining
- Honest miners continue mining on old public chain because they do not know about secret block.

3. Step 3: Selfish Miner Gains Lead
- If selfish miners mine another block:
Private Chain Length > Public Chain Length
Now they have an advantage.

4. Step 4: Strategic Release
- The selfish miners reveal blocks strategically to:
    invalidate honest miners’ blocks,
    force chain reorganization,
    claim more rewards.

- Example Scenario

- Key Concept: Forking
    Selfish mining intentionally creates temporary forks.
- The network eventually follows:
    the longest valid chain.
- This is called the:
    Longest Chain Rule

- Blockchain Rule Used
    Most PoW systems use:
    Longest valid chain = accepted blockchain.
    Selfish miners exploit this rule.

- Orphan Blocks
- Blocks mined honestly but discarded later are called:
    stale blocks,
    orphan blocks.
- Selfish mining increases orphan rates for honest miners.

- Selfish Mining Strategy States
| State    | Meaning                           |
| -------- | --------------------------------- |
| Lead = 0 | Public and private chains equal   |
| Lead = 1 | Selfish miners ahead by one block |
| Lead ≥ 2 | Strong advantage                  |

- Conditions for Successful Selfish Mining
| Requirement            | Reason                 |
| ---------------------- | ---------------------- |
| Significant hash power | Maintain hidden lead   |
| Fast communication     | Release blocks quickly |
| Strategic timing       | Maximize orphaning     |

- Selfish Mining vs 51% Attack
| Selfish Mining             | 51% Attack                    |
| -------------------------- | ----------------------------- |
| Hides blocks strategically | Controls majority hash power  |
| Gains unfair rewards       | Full network control possible |
| Can work below 50%         | Usually requires >50%         |
| Exploits fork behavior     | Can double spend              |

- But selfish mining has not happened yet cz the ASICs used are costly and it can reduce the BC cost.

# Chaff Coins (Mixins)
- Chaff coins or mixins are decoy transaction inputs used in privacy-focused cryptocurrencies to hide the real sender in a transaction.
- They are primarily associated with:
    Monero
    and ring signature–based privacy systems.
- Basic Idea
- When a user spends a coin:
    the real transaction input is mixed with several fake inputs (decoys),
    observers cannot determine which input is actually being spent.
- These fake inputs are called:
    mixins,
    chaff coins,
    decoy outputs.
- Why the Term "Chaff"?
    - The term comes from radar defense systems where:
        aircraft release chaff (fake signals)
        to confuse tracking systems.
- Similarly in blockchain:
    - fake transaction inputs confuse blockchain analysis.

- Role in Privacy
| Privacy Property      | Purpose                     |
| --------------------- | --------------------------- |
| Sender anonymity      | Hide actual spender         |
| Untraceability        | Prevent transaction tracing |
| Plausible deniability | Multiple possible senders   |

# eclipse attack scenario
- An eclipse attack is a network-layer attack in which an attacker isolates a blockchain node by controlling all (or most) of its peer-to-peer connections.
- The victim node receives information only from attacker-controlled peers, causing the attacker to manipulate the node’s view of the blockchain network.
- Eclipse attacks are mainly discussed in:
    Bitcoin,
    peer-to-peer blockchain systems,
    decentralized networks.
- Basic Idea
- Normally:
    - Node ↔ Many Honest Peers
- In an eclipse attack:
    - Victim Node ↔ Attacker-Controlled Peers Only
The victim becomes isolated from the real network.

- Main Goal
    - The attacker wants to:
    manipulate blockchain information,
    delay/block transactions,
    enable double-spending,
    influence mining behavior,
    or prepare larger attacks.

## How Eclipse Attack Works
1. Step 1: Attacker Creates Many Fake Nodes
Attacker controls numerous malicious peers (Sybil nodes).

2. Step 2: Victim Connects to Malicious Peers
The attacker monopolizes the victim’s incoming/outgoing connections.

3. Step 3: Honest Connections Are Blocked
The victim no longer receives genuine blockchain updates.

- Difference Between Eclipse and Sybil Attack
| Eclipse Attack                | Sybil Attack                 |
| ----------------------------- | ---------------------------- |
| Isolates a specific node      | Creates many fake nodes      |
| Targeted attack               | Network-wide identity attack |
| Controls victim’s connections | Inflates attacker presence   |

## Defense Mechanisms
1. Diverse Peer Selection
- Connect to peers from:
    different IP ranges,
    different networks.

2. Connection Limits
- Restrict peer monopolization.

3. Peer Authentication
- Validate trusted peers.

4. Randomized Network Topology
- Reduce predictability.

5. Increased Outbound Connections
More honest peers reduce isolation risk.

- Bitcoin-Specific Protections
    - Bitcoin introduced:
        peer diversity,
        address management improvements,
        eviction protections.

# Fomo3D Smart Contract Game
- Fomo3D was a blockchain-based smart contract game built on: Ethereum.
- It became famous for:
    its “last buyer wins” mechanism,
    game-theoretic economics,
    and vulnerabilities/exploit discussions in blockchain security.
- The game combined:
    gambling mechanics,
    auctions,
    smart contracts,
    token economics,
    and psychological “FOMO” (Fear Of Missing Out).
- Main Concept
    Players purchased virtual “keys.”
- Each key purchase:
    increased the prize pool,
    extended a countdown timer.
- When the timer expired:
    the last player who bought a key won the jackpot.
- Meaning of FOMO
    FOMO = Fear Of Missing Out
- Players continuously bought keys because they feared:
    missing the final jackpot, losing potential rewards.

## Core Gameplay
- Buy Key → Extend Timer → Increase Jackpot
- When timer reaches zero:
    - Last Buyer Wins Jackpot

- Game Flow
1. Step 1: Initial Timer Starts
- The contract begins with a countdown timer.

2. Step 2: Players Buy Keys
- Each purchase:
    adds time,
    increases pot value.

3. Step 3: Competition Intensifies
- Near timer expiration:
    players rapidly buy keys,
    trying to become the final buyer.

4. Step 4: Timer Expires
- The last buyer receives the jackpot.

- Simplified Architecture
```yml
Players → Buy Keys → Smart Contract Pot
                      ↓
                 Last Buyer Wins
```

- Smart Contract Features
The Fomo3D contract included:
| Feature                | Purpose                  |
| ---------------------- | ------------------------ |
| Timer logic            | Controls game duration   |
| Jackpot pool           | Accumulates ETH          |
| Key ownership tracking | Determines winner        |
| Revenue distribution   | Shares profits           |
| Automated payouts      | Smart contract execution |

## Key Economic Mechanism
- Each key purchase:
    increased key price,
    distributed rewards to earlier players,
    increased jackpot pool.
- Incentive Structure
- Players were incentivized because:
    jackpot kept growing,
    earlier buyers received dividends,
    late buyers chased final reward.
- Why It Became Famous
    - Fomo3D became notable because of:
        massive ETH accumulation,
        smart contract game theory,
        transaction manipulation,
        miner advantage discussions.
- Miner Advantage / Transaction Ordering
    - In blockchain systems:
    - miners can influence:
        transaction ordering,
        inclusion timing.
- This became important in Fomo3D because:
the “last transaction” determines winner.

### Front-Running Concerns
- Players attempted:
        Front-running
    - Meaning:
        paying higher gas fees,
        so their transaction executes last.

## Suppression Attack
- A suppression attack is a blockchain/network attack in which an attacker intentionally prevents, delays, or suppresses the propagation of transactions or blocks in the network.

# Double-Spending Attack
- A double-spending attack is a blockchain attack in which the same cryptocurrency is spent more than once.
- The attacker attempts to:
    send cryptocurrency to a victim,
    later reverse or invalidate that transaction,
    and reuse the same coins elsewhere.
- Double spending is a major security concern in digital currencies such as:
Bitcoin.

## How Blockchain Prevents Double Spending
- Blockchain prevents this using:
    distributed consensus,
    transaction validation,
    longest-chain rule,
    confirmations.

## Common Types of Double-Spending Attacks
1. Race Attack
- Attacker sends:
    one transaction to merchant,
    another conflicting transaction to network.
- The attacker hopes:
    merchant accepts payment before confirmation.

2. Finney Attack
- Named after:
Hal Finney.
- Working
    Attacker mines a block privately containing refund transaction.
    Makes payment to merchant.
    Merchant accepts quickly.
    Attacker releases private block.
    Merchant transaction becomes invalid.

3. 51% Attack
- If attacker controls >50% network hash power:
    they can reorganize blockchain,
    reverse transactions,
    double spend.
