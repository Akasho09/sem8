# Project Ubin Phase 2
- Monetary Authority of Singapore’s Project Ubin Phase 2 focused on developing a decentralized inter-bank payment system using blockchain technology for real-time gross settlement (RTGS) of tokenized Singapore dollars.
- It explored how banks could:
    transfer tokenized funds directly,
    settle payments privately,
    and maintain transaction finality on a distributed ledger.
- Background: Project Ubin
- Project Ubin was a multi-phase blockchain initiative launched by:
    - Monetary Authority of Singapore (MAS)
- to study:
    distributed ledger technology (DLT),
    tokenized central bank money,
    interbank settlement systems.
- Focus of Phase 2
    - Phase 2 specifically aimed to:
        improve privacy of transactions,
        support decentralized settlement,
        remove reliance on a central queue manager,
        test DLT-based RTGS mechanisms.
- Main Objective
- Create a blockchain-based payment network where:
    - banks exchange tokenized SGD directly,
    transactions settle securely and efficiently,
    liquidity is managed automatically.
- Core Features of Phase 2
| Feature                | Purpose                                     |
| ---------------------- | ------------------------------------------- |
| Tokenized SGD          | Digital representation of Singapore dollars |
| Decentralized Queueing | Remove central bottleneck                   |
| Privacy Mechanisms     | Confidential bank transactions              |
| Atomic Settlement      | Guaranteed payment completion               |
| DLT-based RTGS         | Real-time interbank settlement              |

- Key Innovation
- The major innovation in Phase 2 was:
- Decentralized Queue Management
    - Traditional RTGS systems use:
        centralized payment queues.
    - Project Ubin explored:
        decentralized liquidity-saving mechanisms.

- Consensus Mechanism
- The project explored permissioned blockchain consensus mechanisms such as:
    PBFT-style systems,
    distributed validation.
- This allowed:
    fast settlement,
    deterministic finality.

## Project Ubin Phase 3 (Delivery versus Payment)
- Monetary Authority of Singapore’s Project Ubin Phase 3 focused on implementing and testing: Delivery versus Payment (DvP) using blockchain/distributed ledger technology (DLT).
- The phase explored how:
    tokenized securities/assets,
    and tokenized cash
    could be exchanged atomically on a distributed ledger without settlement risk.
- Main Goal
    - To ensure:
    Asset delivery and payment occur simultaneously
- This prevents either party from:
    paying without receiving assets,
    or delivering assets without receiving payment.

- What is Delivery versus Payment (DvP)?
- DvP is a settlement mechanism where:
Transfer of asset
AND
transfer of payment
occur together atomically

- Why DvP is Important
Without DvP:
| Risk              | Description                          |
| ----------------- | ------------------------------------ |
| Settlement Risk   | One side fulfills while other fails  |
| Counterparty Risk | Loss due to non-payment/non-delivery |

- Focus of Project Ubin Phase 3
- Phase 3 studied:
    blockchain-based securities settlement,
    atomic exchange mechanisms,
    interoperability between asset and payment ledgers.
- Core Components
| Component            | Purpose                |
| -------------------- | ---------------------- |
| Tokenized Cash       | Digital SGD settlement |
| Tokenized Securities | Digital assets         |
| Smart Contracts      | Automated settlement   |
| Atomic Swap Logic    | Simultaneous exchange  |
| DLT Infrastructure   | Shared ledger          |

## Gridlock (in Payment & Blockchain Systems)
- Gridlock is a situation in a payment or settlement system where transactions cannot be completed because participants are waiting for incoming funds from one another, creating a circular dependency.
- It commonly occurs in:
    interbank payment systems,
    RTGS (Real-Time Gross Settlement) systems,
    blockchain-based settlement networks such as:
    Monetary Authority of Singapore’s Project Ubin.

## Multilateral Netting
- Multilateral netting is a financial settlement mechanism in which multiple obligations among several participants are combined and reduced into a smaller set of net payable or receivable amounts.
- Instead of settling every transaction individually, only the net difference is settled.
- It is widely used in:
    banking systems,
    RTGS optimization,
    clearing houses,
    blockchain-based interbank settlement systems such as:
    Monetary Authority of Singapore’s Project Ubin.

# Stellar Consensus Protocol (SCP)
- The Stellar Consensus Protocol (SCP) is a decentralized consensus mechanism used by: Stellar
to achieve agreement among distributed nodes without relying on mining.
- SCP is based on:
    - Federated Byzantine Agreement (FBA)
    - and enables:
        fast transaction confirmation,
        decentralized trust,
        low energy consumption,
        Byzantine fault tolerance.
- Main Goal of SCP
    - Allow nodes in the network to:
        agree on transaction validity,
        maintain a consistent ledger,
        tolerate malicious/faulty nodes,
        without Proof-of-Work mining.
- Key Features
| Feature                   | Description                |
| ------------------------- | -------------------------- |
| No Mining                 | Energy efficient           |
| Fast Finality             | Quick confirmation         |
| Byzantine Fault Tolerance | Handles malicious nodes    |
| Federated Trust           | Nodes choose trusted peers |
| Decentralized Consensus   | No central authority       |

## Foundation: Federated Byzantine Agreement (FBA)
- Traditional Byzantine systems:
    use fixed validator sets.
- In SCP:
    each node chooses whom it trusts.
- This creates:
    Federated Trust

- Core Idea
    - Instead of global trust:
        Each node selects trusted nodes
        Consensus emerges from overlapping trust groups.
- Important Concepts in SCP
1. Quorum
A group of nodes sufficient to reach agreement.

2. Quorum Slice
A subset of trusted nodes chosen by a node.
- Example:
Node A trusts:
{B, C, D}
- This set is A’s quorum slice.

3. Federated Voting
- Nodes vote based on:
    trusted quorum slices,
    overlapping trust relationships.

## Consensus Process in SCP
- SCP works in phases:
1. Phase 1: Nomination Protocol
Nodes propose candidate values/transactions.

2. Phase 2: Ballot Protocol
- Nodes vote to:
    accept,
    confirm,
    externalize values.
- Result
    - All honest nodes converge on:
    the same ledger state.
```yml
 Vote -> Accept -> Confirm
```

## Why SCP is Fast
- Unlike:
Bitcoin
- SCP does NOT require:
    mining,
    PoW puzzles,
    block competition.
- Thus confirmations are:
    much faster,
    low latency.

- Advantages of SCP
| Advantage                | Description             |
| ------------------------ | ----------------------- |
| Energy Efficient         | No mining               |
| Fast Transactions        | Low latency             |
| Decentralized            | Distributed trust       |
| Byzantine Fault Tolerant | Resists malicious nodes |
| Scalable                 | Efficient communication |

- Challenges
| Challenge                      | Description                          |
| ------------------------------ | ------------------------------------ |
| Trust Configuration            | Poor choices weaken security         |
| Centralization Risk            | Many nodes may trust same validators |
| Quorum Intersection Complexity | Ensuring overlap                     |
| Governance Issues              | Trust management                     |

- Real-World Use
- SCP powers: Stellar
- for:
    cross-border payments,
    token transfers,
    financial settlement.

# CollabFed Decentralized Marketplace Model
- The CollabFed decentralized marketplace model is a collaborative federated marketplace architecture in which multiple independent participants cooperate in a decentralized environment to exchange:
    services,
    data,
    digital assets,
    or computational resources
without relying on a single centralized authority.
- The model combines:
    decentralization,
    federation,
    collaboration,
    trust management,
    and blockchain/distributed ledger concepts.
- Meaning of "CollabFed"
- The term generally combines:
| Term          | Meaning                               |
| ------------- | ------------------------------------- |
| Collaborative | Multiple entities cooperate           |
| Federated     | Independent domains/nodes participate |
| Marketplace   | Exchange platform for services/assets |

- Main Goal
    - To create a marketplace where:
        participants maintain autonomy,
        trust is distributed,
        transactions are coordinated collaboratively,
        and no single entity controls the ecosystem.

- Key Characteristics
| Feature              | Description                         |
| -------------------- | ----------------------------------- |
| Decentralization     | No central controller               |
| Federation           | Independent organizations cooperate |
| Trust Management     | Distributed trust relationships     |
| Interoperability     | Different systems communicate       |
| Privacy Preservation | Controlled data sharing             |
| Smart Contracts      | Automated transactions              |

- Basic Architecture
```yml
Participant A ↔ Marketplace Network ↔ Participant B
                     ↕
               Distributed Ledger
```

## SPV (Simplified Payment Verification)
- Simplified Payment Verification (SPV) is a lightweight method that allows a blockchain client to verify that a transaction has been included in the blockchain without downloading the entire blockchain.
- SPV was introduced in:
    Bitcoin
    by Satoshi Nakamoto in the Bitcoin whitepaper.
- Main Goal
- Enable devices with limited:
    storage,
    bandwidth,
    computation
to verify payments efficiently.

## BLS Signatures
- BLS signatures (Boneh–Lynn–Shacham signatures) are a cryptographic digital signature scheme known for:
    short signature size,
    efficient verification,
    and signature aggregation capabilities.
- Main Features
| Feature                    | Description                  |
| -------------------------- | ---------------------------- |
| Short Signatures           | Compact size                 |
| Aggregation                | Multiple signatures combined |
| Efficient Verification     | Fast validation              |
| Pairing-Based Cryptography | Uses elliptic curve pairings |

- CollabFed combines multiple service provider signatures into a single response by aggregating or bundling the providers’ digital signatures and endorsements into one unified cryptographic proof. 
This allows users to verify that multiple federated providers participated in and approved the response without validating each signature individually, improving efficiency and scalability.
