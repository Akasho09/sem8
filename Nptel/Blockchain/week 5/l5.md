# Ethereum Smart Contracts, Solidity & Deployment

## 🤖 1. What are Smart Contracts?
- Programs executed on blockchain
- Work on ledger data
- Key Features:
    - Read from blockchain
    - Write to blockchain
    - Executed by multiple nodes
- Important:
    - Execution result = Consensus of nodes

## ⚙️ 2. Ethereum Virtual Machine (EVM)
- Execution environment for smart contracts
- Role:
- Executes contract bytecode
- Maintains global state
- Key Idea:
    - EVM = Distributed State Machine

## 🔄 3. State Machine Concept
- Ethereum maintains:
    - Account balances
    - Contract variables
- Each transaction:
    - Old State → Transaction → New State
- Important:
    - State changes must be deterministic

## ⚠️ 4. Deterministic Execution
- Why needed?
    - Same contract executed by many nodes
- Requirement:
    - Same input → Same output (for all nodes)
- Otherwise:
    - ❌ Consensus failure

## 💻 5. Solidity Language
- High-level language for smart contracts
- Features:
    - Statically typed(compile time check).
- Supports:
    - Functions
    - Variables
    - Inheritance
- Syntax inspired by:
    - JavaScript
    - C++

## 🧩 6. Structure of a Smart Contract
```js
contract Storage {
    uint256 positiveNumber;

    function store(uint256 x) public {
        positiveNumber = x;
    }

    function read() public view returns (uint256) {
        return positiveNumber;
    }
}
```
- Components:
    - Contract name
    - State variables
    - Functions

## 🔑 7. Types of Functions
- 🔹 Public
    - Accessible by users
- 🔹 View
    - Read-only
    - No state change
    - No gas required
- 🔹 Non-view
    - Modify state
    - Require gas

## 🔄 8. Compilation Process
- Flow:
    - Solidity Code → Compiler → Bytecode + ABI
- Output:
    - 🔹 Bytecode
        - Executed by EVM
    - 🔹 ABI
        - Interface to interact with contract

## 🔍 9. What is ABI?
- Describes contract functions
- Purpose:
- Used by Web3.js
- Enables function calls
- Contains:
- Function names
- Inputs/outputs

## 🛠️ 10. Remix Editor
- Browser-based IDE
- Features:
    - Write Solidity code
    - Compile contracts
    - Test execution
- Advantage:
    - No setup required

## 🦊 11. MetaMask Wallet
- Purpose:
    - Connect browser to Ethereum
- Features:
    - Create accounts
    - Store private keys
    - Send transactions
- Important:
    - Used for deploying contracts

## 🚀 12. Deploying Smart Contract
1. Write contract
2. Compile in Remix
3. Get:
    - Bytecode
    - ABI
4. Connect MetaMask
5. Deploy contract
- Result:
- Contract gets:
    - Unique Address (like account)

## ⚙️ 13. Executing Smart Contract
- Two Methods:
1. 🔹 Call (Read)
No transaction
No gas
Used for view functions

2. 🔹 Send (Write)
Creates transaction
Requires gas
Used for state-changing functions
Summary:
call → Read
send → Write

## 💸 14. Gas Usage
Required for:
Writing data
Deploying contract
- Not required for:
    - Reading data

## 🔗 15. Interaction using Web3.js
- Requirements:
- Contract ABI
- Contract Address
- Example (Read):
    - contract.methods.read().call().then(console.log);
- Example (Write):
    - contract.methods.store(11).send().then(console.log);
- Important:
.call() → No gas
.send() → Requires gas

## 🔄 16. Full Workflow
```yml
    Write contract (Solidity)
          ↓
    Compile → Bytecode + ABI
          ↓
    Deploy via MetaMask
          ↓
    Get contract address
            ↓
    Use Web3.js
            ↓
    Call / Send functions
```

# 📌 Final Summary
Smart contracts = programmable blockchain logic
Executed by:
EVM
Multiple nodes
Key Components:
Solidity → Write
Compiler → Convert
ABI → Interface
Web3.js → Interaction
