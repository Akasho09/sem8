# Consensus in Blockchain – Part 1

## What is Consensus in Blockchain?
- All nodes must agree on same blockchain
- Why needed?
    - Every node has local copy
- Must ensure:
    - All copies remain consistent
- Goal:
    - Agree on:
        - Next block
        - Valid transactions

## 🌐 2. Permissionless Model (Open Network)
- Network where:
    - Anyone can join
    - Anyone can leave
    - No authorization required
- Example:
    - Bitcoin
    - Ethereum
- Features:
    - No central authority
    - No identity verification (KYC)
    - Uses cryptography for trust

## ⚠️ 3. Challenges in Open Blockchain
1. Unknown Participants
Nodes don’t know each other

2. Anyone can propose block
Multiple blocks at same time

3. Dynamic Network
Nodes join/leave anytime

4. No trust
Some nodes may be malicious

5. Asynchronous communication
- Messages may be:
    - Delayed
    - Lost
    - Out of order

## ⏳ 4. Asynchronous Network
- No guarantee:
    - When message arrives
    - Whether it arrives
- Problems:
    - No global clock
    - Clock drift exists
    - Message delay unpredictable
- Example:
    - Block 3 has Block 1,2and4 connected and all of them are down => Message will be lost.
    - Tho TCP is reliable bur there is no connection to every block from every block.
- Result:
    - 👉 Order inconsistency

## 📡 5. Gossip Protocol
- Message propagation method
- Working:
    - Node → Neighbors → Their neighbors → Entire network
- Key Idea:
    - Multi-hop communication
- Advantage:
    - Scalable
    - Decentralized

## ⚠️ 6. Types of Faults
🔹 1. Crash Fault
Node stops working

🔹 2. Network (Link) Fault
Connection fails
Message not delivered

🔹 3. Byzantine Fault (MOST IMPORTANT)
- Node behaves maliciously
- Example:
- Node sends:
    - Block A → Node 1
    - Block B → Node 2
- Result:
    - Conflicting information

## ⚖️ 7. FLP Impossibility
Statement:
- Consensus impossible in asynchronous system
(even with 1 faulty node)
- Meaning:
- Cannot guarantee:
    - Safety + Liveness together

## ⚖️ 8. Safety vs Liveness
- 🔹 Safety
    - No wrong block added
- 🔹 Liveness
    - System keeps progressing
- Trade-off:
    - Blockchain prioritizes → Liveness
- Meaning:
    - Add blocks quickly
    - Fix errors later

## 👨‍💻 9. Role of Miners
- Nodes that:
    - Collect transactions
    - Propose new blocks
- Key Challenge:
    - Which miner adds next block?

## 📥 10. Unconfirmed Transaction Pool
- List of pending transactions
- Important:
    - Each miner has different pool
- Why?
    - Due to:
        - Network delay
        - Asynchronous communication
- Example:
    - Miner 1 sees T1, T2
    - Miner 2 sees T2, T3
- Result:
    - 👉 Different blocks proposed

## ⚠️ 11. Consensus Challenge
```yml
        Multiple miners → Multiple blocks
                    ↓
        Which block to accept?
```
- Requirement:
    - Fair selection
    - No monopoly
    - Prevent attacker control

## 🔐 12. Key Assumption
- Important:
    >50% nodes are honest
- Why?
    - Ensures:
        - Security
        - Trust

# 📌 Final Summary
Blockchain is distributed system
Consensus needed for:
Agreement
Consistency
Core Challenges:
Unknown participants
Asynchronous network
Faults (especially Byzantine)
No central control
Solution Direction:
👉 Proof of Work (next lecture)
