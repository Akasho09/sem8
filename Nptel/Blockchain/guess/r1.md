## Structure of Blockchain
- A blockchain is a distributed, decentralized ledger made up of a sequence of blocks that store transactions securely using cryptography.
- Each block:
    stores data,
    links to the previous block,
    and forms an immutable chain.

- Basic Structure
Block 1 → Block 2 → Block 3 → Block 4
- Each block contains:
    transaction data,
    hash of current block,
    hash of previous block.

### Main Components of Blockchain Structure
| Component           | Purpose                            |
| ------------------- | ---------------------------------- |
| Block               | Stores transactions/data           |
| Hash                | Unique block fingerprint           |
| Previous Hash       | Links blocks together              |
| Merkle Tree         | Efficient transaction verification |
| Nonce               | Used in mining                     |
| Consensus Mechanism | Validates blocks                   |

### Structure of a Block
- A blockchain block generally has two parts:
Block = Block Header + Block Body

1. Block Header
Contains metadata about the block.
- Common Fields in Block Header
| Field               | Purpose                 |
| ------------------- | ----------------------- |
| Previous Block Hash | Links to earlier block  |
| Merkle Root         | Summary of transactions |
| Timestamp           | Block creation time     |
| Nonce               | Mining value            |
| Difficulty Target   | PoW difficulty          |
| Version             | Protocol version        |
> P.T.M N.DT.V

2. Block Body
- Contains:
    list of transactions,
    smart contract data,
    or other ledger records.

## SHA-256
- SHA-256 (Secure Hash Algorithm 256-bit) is a cryptographic hash function that converts input data of any size into a fixed-size:
    - 256-bit (32-byte) hash value
- It belongs to the:
    - SHA-2 family
- developed by:
    - National Security Agency (NSA).
- Main Purpose
- SHA-256 is used for:
    data integrity,
    digital signatures,
    blockchain mining,
    password hashing,
    cryptographic verification.
- Basic Idea
- Input data:
    - Message/File/Transaction
- is transformed into:
    - Fixed-Length Hash
- Example
- Input:
Hello
- SHA-256 Output:
185f8db32271fe25f561a6fc938b2e264306ec304eda518007d1764826381969

- Important Property
    Even a tiny input change completely changes the output.
- Example:
    Hello
    vs
    hello
produce entirely different hashes.
- This is called:
`Avalanche Effect`
- SHA-256 Output Size
- SHA-256 always produces:
    - 256 bits=32 bytes=64 hexadecimal characters
regardless of input size.

### How SHA-256 Works
1. Step 1: Input Message
Original data provided.

2. Step 2: Padding
Message padded to required block size.

3. Step 3: Block Processing
Data processed in: 512-bit blocks

4. Step 4: Compression Operations
- Uses:
bitwise operations,
modular arithmetic,
logical functions.

5. Step 5: Final Hash Produced
Generates unique 256-bit digest.

### Important Properties of SHA-256
| Property            | Description                            |
| ------------------- | -------------------------------------- |
| Deterministic       | Same input → same hash                 |
| Fixed Length        | Always 256 bits                        |
| Fast Computation    | Efficient hashing                      |
| One-Way Function    | Hard to reverse                        |
| Collision Resistant | Difficult to find same hashes          |
| Avalanche Effect    | Small changes alter output drastically |
> AFFOCD.

## Proof of Work
- Proof of Work (PoW) is a blockchain `consensus mechanism` in which miners solve computationally difficult cryptographic puzzles to validate transactions and create new blocks.
- It is widely used in:
    Bitcoin
    and early blockchain systems.
- Main Goal
- PoW ensures:
    decentralized consensus,
    blockchain security,
    prevention of double spending,
    resistance against malicious attacks.
- Basic Idea
    - Miners compete to solve a mathematical puzzle.
    - The first miner who solves it:
        creates the next block,
        broadcasts it to the network,
        receives rewards.
- Simplified Flow
```yml
Transactions
      ↓
Miners Compete
      ↓
Solve Cryptographic Puzzle
      ↓
Valid Block Added
      ↓
Miner Reward
```
- Why "Work"?
    - The miner must perform:
    large amounts of computation,
    repeated hash calculations.
    - This computational effort is the:
    Proof of Work

- Core Mechanism
    - PoW usually involves finding a value called:
        - `Nonce`
- such that the block hash satisfies a difficulty condition.

- Bitcoin PoW Example
- In:
Bitcoin
- miners repeatedly compute:
> SHA256(SHA256(BlockHeader))
Mining Target Condition
- A valid block hash must satisfy:
    Hash < Target Difficulty

### Mining Process
1. Step 1: Gather Transactions
- Miner collects pending transactions.

2. Step 2: Build Block
- Transactions placed into candidate block.

3. Step 3: Compute Hash
- Miner hashes block header repeatedly.

4. Step 4: Change Nonce
- If hash invalid:
    nonce changes,
    hashing repeated.

5. Step 5: Find Valid Hash
- When condition satisfied:
    miner broadcasts block.

6. Step 6: Network Verification
- Other nodes verify:
    transactions,
    block hash,
    PoW validity.

- Example of Mining
    Nonce = 1 → Invalid Hash
    Nonce = 2 → Invalid Hash
    Nonce = 3 → Valid Hash

- Blockchain Security
    - PoW secures blockchain because:
    rewriting history requires enormous computational power.

## Bitcoin Mining Process
- The Bitcoin mining process is the procedure through which miners:
    validate transactions,
    create new blocks,
    secure the blockchain,
    and earn Bitcoin rewards
using the:
- Proof of Work (PoW) consensus mechanism.

- Mining is fundamental to:
Bitcoin.

- Main Goals of Bitcoin Mining
- Mining helps:
    maintain decentralized consensus,
    prevent double spending,
    secure the blockchain,
    issue new bitcoins.
- Basic Idea
Miners compete to solve a cryptographic puzzle.
- The first miner to solve it:
adds the next block,
receives block reward + transaction fees.

- Simplified Mining Flow
```yml
Pending Transactions
        ↓
Block Formation
        ↓
Proof-of-Work Puzzle
        ↓
Valid Block Found
        ↓
Broadcast to Network
        ↓
Block Added to Blockchain
```

### Step-by-Step Bitcoin Mining Process
1. Step 1: Transaction Collection
- Miners collect:
unconfirmed transactions
from the: Mempool (transaction pool).

2. Step 2: Verify Transactions
- Miner checks:
    digital signatures,
    sufficient balances,
    transaction validity.
- Invalid transactions are rejected.

3. Step 3: Build Candidate Block
- Miner creates a block containing:
    transaction list,
    previous block hash,
    timestamp,
    Merkle root,
    nonce.

4. Step 4: Create Merkle Root
- Transactions are hashed into:
Merkle Tree
- Resulting in:
Merkle Root

5. Step 5: Proof-of-Work Puzzle
- Miner repeatedly hashes the block header using:
SHA-256
- Bitcoin Hash Function
SHA256(SHA256(BlockHeader))

6. Step 6: Nonce Searching
- Miner changes: Nonce
repeatedly to find a valid hash.
- Goal Condition
A valid hash must satisfy:
- Hash<Target Difficulty

7. Step 7: Valid Block Found
- When a valid hash is discovered:
miner broadcasts block to network.

8. Step 8: Network Verification
- Other nodes verify:
PoW validity,
transactions,
block structure.
- If valid:
block accepted.

9. Step 9: Block Added to Blockchain
- New block appended to:
Bitcoin.

10. Step 10: Miner Receives Reward
- Miner earns:
block reward,
transaction fees.

### Bitcoin Block Reward
- Initially:
50 BTC
- Reward halves periodically through:
Halving

- Current Mining Reward Structure
Block Reward + Transaction Fees

### Difficulty Adjustment
- Bitcoin adjusts mining difficulty approximately every:
2016 blocks
to maintain: ≈ 10 minutes per block

## Soft Fork vs Hard Fork
- Forks in blockchain are protocol changes that modify blockchain rules.
- They occur when:
    blockchain software is updated,
    consensus rules change,
    nodes may follow different versions of the protocol.
- Forks are mainly of two types:
    Soft Fork
    Hard Fork

- What is a Fork?
    - A fork means:
    Blockchain rules split into different versions

- Types of Forks
| Type      | Compatibility           |
| --------- | ----------------------- |
| Soft Fork | Backward compatible     |
| Hard Fork | Not backward compatible |

1. Soft Fork 
- A soft fork is a blockchain protocol upgrade that:
    tightens or restricts rules,
    remains compatible with older nodes.
- Older nodes can still:
    recognize new blocks as valid,
    even if they do not fully understand new rules.

- Basic Idea of Soft Fork
>   New Rules ⊂ Old Rules
    (New rules are stricter subset of old rules.)
- Example
    Suppose old rule allowed:
    Block size ≤ 2 MB
- Soft fork changes to:
    Block size ≤ 1 MB
    Older nodes still accept smaller blocks.

- Soft Fork Characteristics:
| Feature                    | Description    |
| -------------------------- | -------------- |
| Backward Compatible        | Yes            |
| Chain Split Risk           | Lower          |
| Requires Majority Adoption | Usually miners |
| Older Nodes Work           | Yes            |

- Real Example of Soft Fork
SegWit (Segregated Witness)
on:
Bitcoin was implemented as a soft fork.

- Advantages of Soft Fork
| Advantage            | Description                  |
| -------------------- | ---------------------------- |
| Easier Upgrade       | Older nodes still function   |
| Less Disruptive      | Reduced network split risk   |
| Better Compatibility | Existing ecosystem preserved |

- Disadvantages of Soft Fork
| Disadvantage       | Description               |
| ------------------ | ------------------------- |
| Limited Changes    | Must remain compatible    |
| Complex Activation | Requires majority support |

2. Hard Fork
- A hard fork is a protocol upgrade that:
    changes blockchain rules incompatibly,
    makes old nodes unable to validate new blocks.

- Basic Idea of Hard Fork
> New Rules ≠ Old Rules
Older software rejects blocks created under new rules.

- Example
- Suppose old rule:
Block size ≤ 1 MB
- Hard fork changes to:
Block size ≤ 8 MB
- Old nodes reject these blocks.

- Hard Fork Characteristics
| Feature                | Description |
| ---------------------- | ----------- |
| Backward Compatible    | No          |
| Chain Split Possible   | Yes         |
| All Nodes Must Upgrade | Ideally yes |
| Creates New Blockchain | Sometimes   |

- Result of Hard Fork
    - Two blockchains may exist simultaneously:
    original chain,
    upgraded chain.

- Real Example
    - Bitcoin Cash
    forked from: Bitcoin
    through a hard fork.

- Ethereum Hard Fork Example
    - After:
    The `DAO Hack`
    - Ethereum split into:
        Ethereum
        `Ethereum Classic`

- Why Forks Occur
| Reason                   | Purpose               |
| ------------------------ | --------------------- |
| Security Fixes           | Patch vulnerabilities |
| Feature Upgrades         | Add functionality     |
| Scalability Improvements | Better performance    |
| Governance Disagreements | Community conflict    |

- Soft Fork vs Hard Fork Comparison
| Feature             | Soft Fork           | Hard Fork               |
| ------------------- | ------------------- | ----------------------- |
| Compatibility       | Backward compatible | Not backward compatible |
| Chain Split         | Usually avoided     | Possible/common         |
| Old Nodes Valid?    | Yes                 | No                      |
| Upgrade Requirement | Partial majority    | Broad/full adoption     |
| Risk                | Lower               | Higher                  |
