## Ethereum Nonce
- In:
Ethereum,
- a nonce is a number associated with an account that represents:
    - the `count of transactions sent` from that account.
- Nonce ensures:
    transaction ordering,
    uniqueness,
    replay prevention.
- Meaning of Nonce
- Nonce stands for:
    "Number used once"
- Main Purpose
- Ethereum nonce helps:
    prevent duplicate transactions,
    maintain correct transaction order,
    stop replay attacks.
- Basic Idea
Every Ethereum account maintains a nonce.
- When an account sends:
    its first transaction → nonce = 0
    second transaction → nonce = 1
    third transaction → nonce = 2
    and so on.
- Why Nonce is Important
- Without nonce:
    - attackers could replay old signed transactions repeatedly.
    - Nonce prevents this.
- Ethereum Transaction Structure
- An Ethereum transaction includes:
    sender,
    receiver,
    value,
    gas,
    nonce,
    signature.
- Simplified Structure
```yml
Transaction
   ↓
Nonce Included
   ↓
Signed by Sender
Replay Protection
```
- Suppose attacker copies old transaction.
- If nonce already used:
Network rejects duplicate nonce

### Example of Replay Prevention
- If Alice already used:
Nonce = 5
- then another transaction with nonce 5:
becomes invalid.

- Pending Transactions
- If transaction with nonce 3 is pending:
nonce 4 transaction waits.
- This creates:
`Sequential Dependency`

- Ethereum Nonce vs Bitcoin Nonce
| Ethereum Nonce      | Bitcoin Mining Nonce   |
| ------------------- | ---------------------- |
| Transaction counter | Mining puzzle variable |
| Per-account value   | Per-block mining value |
| Prevents replay     | Used in PoW            |

### Nonce and Gas Replacement
- Ethereum allows:
    Transaction Replacement
- A user may resend:
    same nonce,
    higher gas fee.
- This can:
    replace stuck pending transactions.

## Hyperledger Fabric MSP & Channels
- Hyperledger Fabric is a permissioned blockchain platform designed for enterprise applications.
- Key features:
    Permissioned network
    Modular architecture
    Smart contracts called chaincode
    High privacy and scalability
1. MSP (Membership Service Provider)
- MSP is the component in Hyperledger Fabric that manages:
    Identity
    Authentication
    Authorization
- It defines who is allowed to participate in the blockchain network.
- Purpose of MSP
- MSP ensures:
    Only verified organizations/users join the network
    Transactions are signed by valid identities
    Access control is enforced
### Functions of MSP
1. Identity Management
- Each participant gets:
    Digital certificate
    Public/private key pair
- Usually issued by a:
    `Certificate Authority (CA)`

2. Authentication
- MSP verifies:
    Transaction signatures
    User certificates

3. Authorization
- MSP checks:
    What operations a member can perform
    Which organization the member belongs to

- Components of MSP
| Component            | Purpose              |
| -------------------- | -------------------- |
| CA Certificates      | Trust root           |
| Admin Certificates   | Identify admins      |
| Signing Certificates | User identities      |
| Private Keys         | Digital signatures   |
| TLS Certificates     | Secure communication |

### Types of MSP
1. Local MSP
- Used by:
    Peer
    Orderer
    Client
Controls identity for a specific node.

2. Channel MSP
Defines organizations participating in a channel.

### 2. Channels in Hyperledger Fabric
- A channel is a:
    - Private communication subnet within a Fabric network.
- Only authorized organizations can access data inside a channel.
- Why Channels Are Needed
- Channels provide:
    Privacy
    Data isolation
    Confidential transactions
- Different organizations may not want to share all data with everyone.
- Features of Channels
    - Private Ledger
        - Each channel has:
            Separate blockchain ledger
            Separate smart contracts
            Separate transaction history
    - Data Confidentiality
        - Only channel members can:
            View transactions
            Execute chaincode
            Access ledger data
    - Independent Governance
        - Each channel can define:
            Policies
            MSPs
            Access rules
        
### Channel Architecture
- Example:
- Network contains:
Bank A
Bank B
Insurance Company
- Possible channels:
| Channel   | Participants       |
| --------- | ------------------ |
| Channel 1 | Bank A + Bank B    |
| Channel 2 | Bank A + Insurance |
| Channel 3 | All organizations  |
- Each channel maintains:
    Independent ledger
    Independent smart contracts

### How Channels Work
- Step-by-Step
1. Channel Creation
Organizations create a channel configuration.

2. Join Channel
Peers join the channel.

3. Install Chaincode
Smart contract installed on channel peers.

4. Execute Transactions
Only members of that channel can transact.

- MSP vs Channel
| Feature  | MSP                          | Channel                 |
| -------- | ---------------------------- | ----------------------- |
| Purpose  | Identity management          | Privacy & communication |
| Handles  | Authentication/authorization | Data isolation          |
| Controls | Who can join                 | Who can access ledger   |
| Based On | Certificates                 | Network partitioning    |

- Important Terms
| Term              | Meaning                      |
| ----------------- | ---------------------------- |
| CA                | Certificate Authority        |
| X.509 Certificate | Digital identity certificate |
| Peer              | Node maintaining ledger      |
| Orderer           | Orders transactions          |
| Chaincode         | Smart contract               |
| Ledger            | Blockchain data              |
