## Bitcoin-NG
- Bitcoin-NG (Next Generation) is:
A blockchain consensus protocol designed to improve the scalability and transaction throughput of Bitcoin.
- It separates:
    Leader election
    Transaction serialization
to increase performance without

- Why Bitcoin-NG Was Introduced
    - Traditional Bitcoin faces limitations:
| Problem            | Description                 |
| ------------------ | --------------------------- |
| Low Throughput     | Few transactions per second |
| High Latency       | Slow confirmation time      |
| Scalability Issues | Large blocks create forks   |

- Bitcoin-NG solves these by:
    Reducing mining bottlenecks
    Allowing faster transaction processing

- Main Idea of Bitcoin-NG
    - Bitcoin-NG divides blocks into two types:
| Block Type  | Purpose              |
| ----------- | -------------------- |
| Key Blocks  | Elect leader/miner   |
| Microblocks | Contain transactions |

1. Key Blocks
- Used to:
- Elect the next leader
- Features
    Mined using Proof of Work (PoW)
    Similar to Bitcoin mining
    Generated less frequently
- Key Block Contains
    Public key of leader
    PoW solution
    Reference to previous block

2. Microblocks
- Contain:
    Actual transactions
- Features
    Created by current leader
    No Proof of Work needed
    Generated rapidly

### Working of Bitcoin-NG
Step-by-Step
1. Mining Key Block
Miners compete using PoW.
- Winner becomes: Leader

2. Leader Creates Microblocks
- Leader generates:
    Multiple microblocks
    Includes transactions quickly

3. Next Key Block
- Another miner mines next key block.
Leadership changes.

- Advantages of Bitcoin-NG
| Advantage          | Description                                 |
| ------------------ | ------------------------------------------- |
| Higher Throughput  | More transactions processed                 |
| Lower Latency      | Faster confirmations                        |
| Better Scalability | Handles larger transaction load             |
| Reduced Forks      | Less competition between transaction blocks |

- Difference Between Bitcoin & Bitcoin-NG
| Feature           | Bitcoin           | Bitcoin-NG               |
| ----------------- | ----------------- | ------------------------ |
| Block Type        | Single block type | Key blocks + microblocks |
| PoW Usage         | Every block       | Only key blocks          |
| Throughput        | Lower             | Higher                   |
| Transaction Speed | Slower            | Faster                   |
| Scalability       | Limited           | Improved                 |

- Limitations
| Limitation                 | Description                            |
| -------------------------- | -------------------------------------- |
| Leader Centralization Risk | Temporary leader has more control      |
| Microblock Conflicts       | Possible if leadership changes quickly |
| More Complex Design        | Compared to traditional Bitcoin        |


## Collective Signing
- A cryptographic protocol where multiple participants collaboratively generate a single collective digital signature.
- Instead of:
    Many separate signatures
- CoSi produces:
    One compact signature representing approval from a group.

### Purpose of CoSi
- CoSi is designed to:
    Improve scalability
    Reduce communication overhead
    Increase trust in distributed systems
- Used in:
    Blockchain
    Distributed consensus
    Byzantine fault tolerant systems

### Main Idea
- Suppose:
    100 validators approve a block
- Instead of storing:
    100 separate signatures
- CoSi combines them into:
    1 collective signature
- that proves:
    Majority/group approval.

### Why CoSi is Needed
- In distributed systems:
    Many nodes sign messages
    Signature verification becomes expensive
- Problems:
    Large communication cost
    Large storage requirement
    Slow verification
- CoSi solves this using:
    Signature aggregation

### Working of CoSi
Step-by-Step
1. Leader Sends Proposal
- Leader broadcasts:
    Transaction
    Block
    Message
to participants.

2. Participants Verify
- Each node:
    Checks validity
    Approves/rejects

3. Partial Signatures Generated
- Approving nodes create:
    Partial signatures

4. Signature Aggregation
- Partial signatures are combined into:
    One collective signature.

5. Verification
- Anyone can verify:
    Single signature
    instead of many signatures.
