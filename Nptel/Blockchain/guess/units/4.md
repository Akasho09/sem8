## Byzantine Fault Tolerance (BFT)
1. Case: 1 Commander + 2 Lieutenants
    > Cannot achieve consensus

2. Case: 1 Commander + 3 Lieutenants
    > Majority → Consensus achieved
=>
> Total Nodes ≥ 3F + 1
Where:
F = number of Byzantine faulty nodes

## Transaction Finality
- Assurance transaction cannot be reversed
- Once confirmed → permanent
- Types:
1. Probabilistic Finality → Bitcoin
2. Deterministic Finality → PBFT
- Importance:
    Prevents double spending
    Ensures trust

## Ethereum Basics
- Open-source blockchain platform
- Supports:
    Smart contracts
    Decentralized applications (DApps)
- Native cryptocurrency:
Ether (ETH)
- Uses:
    Payments
    Gas fees
    Smart contract execution

## Ethereum Accounts
1. Externally Owned Account (EOA)
Controlled by private key
Used by users

2. Contract Account
Controlled by smart contract code
- Account contains:
    Address
    Balance
    Nonce
    Storage

## Nonce in Ethereum
- Counter tracking transactions from account
- Prevents duplicate/replay transactions
- Uses:
Maintain transaction order
Prevent replay attacks
- For EOAs:
Nonce=Number of transactions sent

## Replay Attacks
- Attacker resends valid transaction maliciously
Occurs mainly after blockchain forks.
- Prevention:
    Chain IDs
    Nonces
    Signature verification

## Gas Mechanism
- Gas = fee required to execute operations in Ethereum
- Measures:
    Computational work
- Formula:
  >  Transaction Fee= Gas Used×Gas Price
- Where:
    Gas Used → computation consumed
    Gas Price → price per gas unit
- Purposes:
    Prevent spam
    Allocate resources
    Reward validators
- Example operations:
    ETH transfer
    Smart contract execution
    Token transfer
