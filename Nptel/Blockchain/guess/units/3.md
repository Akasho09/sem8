## Bitcoin Architecture
- Main components of Bitcoin system:
    - Nodes → computers maintaining blockchain
    - Blockchain → distributed ledger
    - Miners → validate transactions and create blocks
    - Wallets → store public/private keys
    - Transactions → transfer Bitcoins
    - Consensus → Proof of Work (PoW)
- Features:
    Decentralized
    Peer-to-peer (P2P)
    Trustless
    Transparent

## Bitcoin Halving
- Block reward reduced by 50%
- Occurs every:
> 210,000 blocks
(~4 years)
- Examples:
- 50 BTC → 25 BTC → 12.5 BTC → 6.25 BTC …
- Purpose:
    Control Bitcoin supply
    Reduce inflation
- Maximum supply:
21 million BTC

## 
### Nonce
“Number used once”
- Arbitrary value changed repeatedly during mining
    Used to generate different hashes
- Purpose:
    Achieve valid hash below target

### Difficulty Target
- Defines mining difficulty
    Lower target → harder mining
- Condition:
    Hash<Target
- Bitcoin adjusts difficulty every:
> 2016 blocks
(~2 weeks)
- Purpose:
    Maintain ~10 minute block time.

### Hash Puzzle
- Miners solve:
> SHA256(Block Header)<Target
- Requires:
    Trial and error
    Brute force hashing
    No shortcut exists.

### Probability in Mining
- Mining success is probabilistic
More hash power → higher probability of finding block
- Probability:
P∝ Miner Hash Rate / Total Network Hash Rate
- Mining is based on chance/luck.

### Binary Leading Zeros Concept
- Valid Bitcoin hash must begin with required leading zeros in binary/hexadecimal form.
- Example:
    - 000000abc45...
- More leading zeros:
    Lower target
    Higher difficulty
    More computation required

### Block Generation Time
- Average Bitcoin block creation time:
10 minutes
- Maintained by difficulty adjustment.
- Importance:
    Stable transaction confirmation
    Predictable Bitcoin issuance
    Network synchronization
