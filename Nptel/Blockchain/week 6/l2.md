# state Machine Replication, Crash Fault Tolerance & Paxos Intro

## 🔁 1. State Machine Replication (SMR) as Consensus
- Each node maintains same state machine
- Goal:
    - All replicas → Same state
- Mapping to Blockchain:
    - Blockchain consensus = agreement on state/value
    - SMR = agreement on state of system
- Insight:
    - 👉 SMR naturally fits permissioned blockchain consensus

## 🔗 2. Why SMR Works in Permissioned Blockchain?
1. Reason 1: Closed Network
- Nodes are known
- Can communicate directly

2. Reason 2: No Mining Needed
- Message Passing replaces Mining
- Benefit:
- No energy waste
- Faster consensus

3. ⚠️ 3. Need for Consensus Still Exists
- Even in permissioned systems:
- Nodes may fail
- Nodes may act maliciously
- Example:
    - One node gives incorrect state
- Solution:
    - Majority voting → Correct state

## 🛡️ 4. Types of Faults
1. 🔹 Crash Fault (CFT)
- Node stops working
- Sends no messages

2. 🔹 Byzantine Fault
- Node behaves maliciously
- Sends wrong/different data

- Key Difference:
| Fault     | Behavior           |
| --------- | ------------------ |
| Crash     | Silent failure     |
| Byzantine | Malicious behavior |

## ⏳ 5. Synchronous vs Asynchronous Systems
1. 🔹 Synchronous System
- Fixed time bound
- Messages arrive on time

2. 🔹 Asynchronous System
- No time guarantee
- Messages can be:
    - Delayed
    - Lost
    - Out of order
- Problem:
- Cannot distinguish:
    - Delay vs Node Failure

## ⚠️ 6. FLP Impossibility (Revisited)
> Consensus impossible in asynchronous system with even 1 crash fault
- Meaning:
    - Cannot guarantee both:
        - Safety
        - Liveness
- Approach:
    - 👉 Prioritize Safety over Liveness

## ⚖️ 7. Consensus Properties
1. 🔹 Validity
If all propose value v → decide v

2. 🔹 Agreement
No two nodes decide differently

3. 🔹 Termination
All nodes eventually decide
- Important:
- PoW:
    Strong liveness
    Weak agreement
- CFT:
    Strong agreement
    Weak liveness

## 🗳️ 8. Majority Voting Concept
- Nodes exchange messages
- Decide based on majority
- Example:
    - 3 out of 5 nodes agree → Consensus
- Key Insight:
    - Handles faulty nodes

## 🔢 9. 2F + 1 Rule (VERY IMPORTANT)
> Total Nodes ≥ 2F + 1
Where:
- F = Number of faulty nodes
- Example:
- F = 2 → Need 5 nodes
- Why?
    - Majority must be honest

## 🧠 10. Consensus in Asynchronous System
- Challenge:
    - Messages delayed
    - Nodes may crash
- Solution:
- Wait for majority responses
- Example Insight:
    - Even with delays → Eventually consensus reached

## ⚙️ 11. Introduction to Paxos
- Fundamental CFT consensus algorithm
- Proposed by:
    - 👉 Leslie Lamport
- Key Idea:
```yml
    Nodes exchange messages
        ↓
    Agree on value
        ↓
    Ensure consistency
```
- Important:
    - Works in asynchronous systems
    - Handles crash faults
- Used in:
    - Distributed databases (e.g., DynamoDB)

# 📌 Final Summary
SMR = foundation of consensus
Permissioned blockchain uses:
Message passing
Majority voting
Core Flow:
Transactions → Ordered → Executed
↓
Nodes reach same state
↓
Majority agrees
↓
Consensus achieved
