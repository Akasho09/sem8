# Permissioned Blockchain & State Machine Replication

## 🔐 1. Permissioned Blockchain Model
- A closed blockchain network
- Only authorized users can join
- Key Feature:
    - Users must be authenticated before joining

### Difference from Permissionless:
| Feature  | Permissionless | Permissioned                    |
| -------- | -------------- | ------------------------------- |
| Access   | Open           | Restricted                      |
| Identity | Unknown        | Known                           |
| Trust    | Low            | Partial (known but not trusted) |

- 👉 Users know each other but may not trust each other

## 🏢 2. Membership Service Provider (MSP)
- Role:
- Handles:
    - Authentication
    - Authorization
- Function:
    - User → MSP → Verified → Join network
- Purpose:
    - Ensure only valid participants enter system

## ⚠️ 3. Why Consensus is Still Needed?
- Even though users are known:
- They may be competitors
- They may act maliciously
- Example:
    - Supply chain companies
    - Competing businesses
- Requirement:
    - Agreement required on valid data

## 📦 4. Smart Contracts in Permissioned Blockchain
- Programs that automate agreements
- Example:
    - Buyer–Seller contract
    - Supply chain tracking
- Key Idea:
    - Contract executes automatically based on events

## 🔄 5. Event-Based Execution
- Store contract on blockchain
- Event occurs (e.g., delivery)
- Contract executed
- Output recorded as transaction
- Example:
- Goods delivered → Trigger contract → Record transaction

## ⚙️ 6. Execution Strategy
- Question:
- 👉 Should every node execute contract?
- Solution:
    - Execute on subset of nodes
- Why?
    - Reduce computation
    - Improve efficiency
- Then:
    - Share result with all nodes

## 🔐 7. Proof & Validation
- Nodes sign results using digital signatures
- Purpose:
    - Proof = Majority nodes agree on result
- Outcome:
    - Validated state accepted

## 🔄 8. Smart Contract as State Machine
- Smart contracts represented as:
    - State → Input → New State
- Why?
    - Deterministic execution
    - Easier consensus
- Important:
    - 👉 Blockchain itself = State Machine

## 🔁 9. State Machine Replication (SMR)
- Replicate same state machine across nodes
- Process:
    - Copy state machine to all nodes
    - Execute transactions
    - Reach same final state
- Key Idea:
    - Same input → Same state across nodes

## 🔢 10. Transaction Ordering
- Problem:
- Multiple transactions arrive
- Solution:
    - Agree on order of execution
- Example:
    - T1 → T2 (same order on all nodes)
- Importance:
    - Ensures consistency

## ⚙️ 11. Execution Process (SMR)
Steps:
```yml
Client → Submit transactions
↓
Consensus on order
↓
Each node executes locally
↓
Reach final state
↓
Compare states
```

## ⚖️ 12. Majority Voting (Fault Tolerance)
- Problem:
    - Some nodes may be faulty
- Example:
Node 1 → State S2
Node 2 → State S2
Node 3 → State S3 (faulty)

- Solution:
    - Majority wins → Final state = S2
- Key Insight:
    - System tolerates faulty nodes

## 🛡️ 13. Fault Tolerance
- Types of faults handled:
    - Crash faults
    - Byzantine faults
- Requirement:
    - Majority of nodes must be honest

# 📌 Final Summary
Permissioned blockchain = controlled network
Uses:
Authentication (MSP)
Consensus
Core Mechanism:
Smart Contract → State Machine
↓
Replicated across nodes
↓
Execute transactions
↓
Reach consensus via majority
