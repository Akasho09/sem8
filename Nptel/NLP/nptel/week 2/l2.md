# 🔹 2. Why Equal Cost is NOT Ideal
- 👉 Not all errors are equally likely!
- 📌 Example
Substituting a → e (common mistake)
Substituting a → m (rare mistake)
❌ Same cost → incorrect modeling
✅ Should assign different weights

## 🔹 3. Weighted Edit Distance
- Assign different costs based on:
Character type
Error frequency
- 🔹 Key Principle
👉 Common mistakes → LOW cost
👉 Rare mistakes → HIGH cost

## 🔹 4. Confusion Matrix
- A table showing:
How often one character is mistaken for another
- Example insights:
a → e (frequent)
vowels errors common (a, e, i, o)
keyboard proximity errors:
m ↔ n
t ↔ y
- 🎯 Insight
- Errors depend on:
Pronunciation similarity
Keyboard layout

## 🔹 5. Modified Dynamic Programming Formula
- Earlier:
```yml
D[i][j] = min(
  D[i-1][j] + 1,
  D[i][j-1] + 1,
  D[i-1][j-1] + cost
)
```
- 🔹 Now (Weighted Version)
```yml
D[i][j] = min(
  D[i-1][j] + del_cost(x_i),
  D[i][j-1] + ins_cost(y_j),
  D[i-1][j-1] + sub_cost(x_i, y_j)
)
```
👉 Cost depends on actual characters

## 🔹 6. Transposition (New Operation)
Swap adjacent characters
- Example:
"al" → "la"
- 📌 Also called:
> Metathesis
- 🔹 Why important?
Very common typing mistake
- 🔹 Condition
- If:
x[i-1] == y[j]
x[i]   == y[j-1]
- 🔹 Formula Addition
D[i][j] = min(
  existing cases,
  D[i-2][j-2] + transpose_cost
)

## 🔹 11. Symmetric Delete Algorithm (IMPORTANT)
- Instead of:
❌ Generating all edits
- 👉 Do only deletions
- 🔹 Steps
🔸 Offline (Dictionary Preprocessing)
- For each word:
Generate all forms with 1–2 deletions
Store them
- 🔸 Runtime
For query word:
Generate delete variants
Match with stored dictionary
- 🔹 Example
Word:
wotld (wrong)
world (correct)
- Delete variants:
wold
otld
wtld
- 👉 Match with dictionary entries
- 🎯 Advantage
Much fewer combinations
Efficient at runtime
