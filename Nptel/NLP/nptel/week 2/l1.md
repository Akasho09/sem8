## 🔹 5. Edit Distance (Core Concept)
Minimum number of operations required to convert one string into another.

- 🔹 Allowed Operations
1. Insertion
Add character
"behaf" → "behalf"
2. Deletion
Remove character
3. Substitution
Replace character

## 🔹 Cost Variants
1. Levenshtein Distance
All operations cost = 1

2. Weighted Version
Substitution = 2
Insert/Delete = 1

## 🔹 7. Naive Approach (Bad)
- Try all possible edits:
Insert everywhere
Delete everywhere
Substitute everywhere
- ❌ Problem:
Exponential complexity
Many useless paths

## 🔹 8. Dynamic Programming Solution
- Break into smaller subproblems
- 🔹 Matrix Definition
- Let:
X length = n
Y length = m
- Define:
D[i][j] = edit distance between:
first i chars of X
first j chars of Y
- 🔹 Final Answer
D[n][m]

## 🔹 9. Initialization
- From lecture :
D[i][0] = i   (delete all characters)
D[0][j] = j   (insert all characters)

## 🔹 10. Recurrence Relation
For each cell:
```yml
D[i][j] = min(
    D[i-1][j] + 1,        // deletion
    D[i][j-1] + 1,        // insertion
    D[i-1][j-1] + cost    // substitution
)
```
- Where:
cost = 0 if characters match
cost = 1 or 2 if different

## 🔹 12. Alignment (Important)
- Shows:
Where insertions happened
Where deletions happened
Where substitutions happened
- 🔹 Example Idea
intention
execution
Alignment shows mapping between characters

- 🔹 Backtracking
- After filling matrix:
Start from D[n][m]
- Move backward:
diagonal → substitution/match
up → deletion
left → insertion

## 🔹 13. Complexity
From lecture :
- ⏱ Time Complexity
O(n × m)
- 💾 Space Complexity
O(n × m)
- 🔙 Backtracking
O(n + m)

## 🔹 14. Why This is Efficient
Compared to naive:
Avoids recomputation
Stores intermediate results
Guarantees optimal solution
